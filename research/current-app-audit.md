## 9. Rebuild implications (for the design-system step)

- **Do not copy the compact system as-is:** it is a JS-threshold + container-query patchwork (1024 px threshold, 560 px container queries, 36 px targets, two accent fallbacks) that the repo's own architecture review (2026-10-22) says is "not yet suitable to claim mobile design complete". The user decision to discard old mobile is consistent with the evidence.
- **Single source of truth needed first:** one token file (colors incl. the 6 undefined `--color-*`, typography incl. a 16 px input floor, spacing, radii, breakpoints, 44 px targets, safe-area), one Naive theme override file (replace the 925-line `naive-theme.ts` + scattered `--n-*` overrides), one modal primitive (`AdaptiveModal`, 28 importers — the de-facto standard), one output implementation (`OutputDisplayCore`, 930 lines).
- **Scope decisions to lock before building:** dead components in §7 #9 (delete vs carry), `TestAreaPanel` vs the live test panels, Arena's multi-column model on a phone, the Optimize/Test hidden-pane pattern (§7 #6), and the vi-VN locale (~3,750 lines, §5).
- **E2E before rebuild:** add a mobile Playwright project (Honor Magic6 viewport, measured on-device) and a `replay`-only gate; the current `gate` group covers only 4 specs and no mobile viewport (§6.2). VCR fixtures exist for optimize/test/analysis but not for save-favorite or image-multiimage analysis.
- **Related file already in `research/`:** `research/astryx-foundations.md` (pre-existing, not written by this audit) — check it before writing the Astryx-derived token mapping, to avoid duplicating that work.
